# Typing Me — development guide

Everything about building, regenerating and testing the project. For the player-facing overview,
download links and screenshots, see the [README](../README.md) at the repo root.

The game: a 2D typing-action game for Windows and macOS, built in Unity. English words fall toward
a stylised keyboard bar; type them before they cross the bottom line. Every word you clear damages
the level's boss — bring it down to finish the level, miss three words and the run ends.

The campaign is **80 levels across 4 seasons** (Spring → Summer → Autumn → Winter), 19 ordinary
levels and a season boss each, with boss ranks climbing `D` → `A` inside every season and `S`
reserved for the season boss. **Each season owns the game's look and feel**: palette, ambient
weather and word motion all belong to the season being played, and the only way to change them is
to beat the season. See [Campaign](#campaign-seasons-ranks-and-bosses).

## Opening the project

- **Editor:** Unity `6000.5.8f1` (already installed). Open `/Users/imac/Developer/typer` from Unity Hub.
- Build order is `Splash` → `Menu` → `Game`. Press Play from any of them; a runtime bootstrap spawns
  the persistent services either way, so each scene runs standalone.

### Splash

`Assets/Video/AysappsSplash.mp4` plays full-screen on launch and hands off to `Menu`. Any key or
click skips it. It renders through a RenderTexture into a RawImage rather than `CameraNearPlane`,
which does not composite reliably under URP, and the handoff is guarded by a timeout so a clip that
fails to prepare can never strand the player on a black screen. `SplashController` logs one line per
run — duration, why it ended, decoded frame count, and the measured brightness of the surface — so
"played" can be told apart from "silently fell through".

> **⚠ Built-in modules are not implicit here.** `manifest.json` lists only what the project needs, and
> the rest of Unity's built-in modules arrive as transitive dependencies. `com.unity.modules.video`
> is not one of them — it had to be added explicitly, or `UnityEngine.Video` does not exist and the
> splash will not compile. The same will apply to any other module you start using.

### Regenerating assets

Every ScriptableObject, prefab and scene in this project is **generated from code** by
`Assets/Editor/ProjectBootstrap.cs`. To rebuild them after changing the generator:

- Menu: **Typing Me → Rebuild Project Assets**, or
- Headless:

```bash
/Applications/Unity/Hub/Editor/6000.5.8f1/Unity.app/Contents/MacOS/Unity -batchmode -quit -projectPath /Users/imac/Developer/typer -executeMethod TypingMe.EditorTools.ProjectBootstrap.RunAll -logFile /tmp/bootstrap.log
```

Scenes and prefabs are built programmatically rather than hand-authored so the project can be
regenerated deterministically and reviewed as source rather than as YAML.

> **One exception: `Assets/Art/` is authored art, not generated by the bootstrap.** The five boss
> sprites in `Assets/Art/Bosses/` are hand-made; a rebuild pins their import settings (Sprite,
> point filter, uncompressed, no mipmaps) and fails loudly if one is missing, but never creates or
> overwrites them. The app icon `Assets/Art/Icon/AppIcon.png` is composed from the dragon sprite by
> `docs/tools/make_icon.py` (Python + Pillow); the bootstrap assigns it as the player's default
> icon, which Unity scales into the macOS `.icns` and Windows `.exe` resources at build time.

> **⚠ Tuning assets do not track code.** `LevelTuning.asset` and `BossTuning.asset` are **create-only**
> — a rebuild deliberately keeps them so a playtest tweak in the inspector survives. The cost is that
> editing the field initialisers in `LevelTuningSO` / `BossTuningSO` does **not** change the assets,
> and they silently drift. This has already caused one bug (a stale `maxSpeed` capped two different
> levels to the same value and made a season boss no harder than the level before it). A rebuild now
> logs which tuning assets it kept; to force them back to code defaults use
> **Typing Me → Reset Tuning Assets to Code Defaults**, or:

```bash
/Applications/Unity/Hub/Editor/6000.5.8f1/Unity.app/Contents/MacOS/Unity -batchmode -quit -projectPath /Users/imac/Developer/typer -executeMethod TypingMe.EditorTools.ProjectBootstrap.ResetTuningAssets -logFile /tmp/reset.log
```

## Architecture

Follows §9 of the design brief.

```
Assets/Scripts/
  Core/      AppBootstrap, GameManager, GameStateMachine, SaveSystem
  Gameplay/  LevelGenerator, LevelRunner, WordSpawner, WordController, InputRouter, MistakeTracker,
             BossGenerator, BossController
  Data/      WordBankSO, LevelTuningSO, BossTuningSO, ThemeSO, LevelData, WordTier,
             Season/SeasonCatalog, BossRank, BossAttack, BossDefinition
  UI/        HomeUI, SettingsUI, LevelSelectUI, LevelButton, KeyboardVisualUI, KeyboardKeyView,
             HudUI, BossUI, RankUpUI, FinaleUI, GameEndPanel, BottomNav, ThemeManager
  Fx/        Juice, ThemedGraphic, GradientBackground, ScrollingTexture, ShardBurst,
             SeasonalAmbientFx
  Audio/     AudioManager, ProceduralMusic, ProceduralSfx
Assets/Editor/   ProjectBootstrap, SceneBuilder, UiFactory, Wiring, SceneValidator,
                 BuildTools, LevelInspector
Assets/Tests/    EditMode/ LevelGenerationTests, MistakeTrackerTests, SeasonAndBossTests
                 PlayMode/ GameplayLoopTests
```

**Responsibility split**

| Piece | Owns |
|---|---|
| `GameManager` | Session flow across scenes: current level, transitions, saving. Persistent. |
| `LevelRunner` | One level's runtime inside the Game scene. Decides win/lose. |
| `WordSpawner` | Spawn cadence, throw placement, the list of live words. |
| `WordController` | One word's matched-length state and per-letter highlighting. |
| `InputRouter` | Character events → the locked word. Owns the targeting rule. |
| `MistakeTracker` | The 3-miss rule, in one place. |
| `BossController` | Boss health, sigil damage and the attack schedule. No scene knowledge. |
| `BossUI` | The boss's body: per-rank archetype, patrol, telegraph. Words launch from it. |
| `RankUpUI` | The rank-clear interstitial, including the live next-boss teaser and the season handover. |
| `FinaleUI` | The campaign finale: coronation, word-by-word tribute, trophies, new-journey reset. |
| `ThemeManager` | The season → palette rule. Applies a season's theme; nothing else may set one. |

**Targeting rule (§9).** On a keystroke with nothing locked, the router picks the *lowest* live word
whose next unmatched letter equals the typed character, and stays locked until that word is cleared
or lost. The lock is a guess the player can overrule by typing: with `taste` and `trip` both live,
`t` locks the lower one, but if the next key continues the *other* word (`r` → `tr…`), the lock and
its typed progress **re-route** to that word (lowest candidate wins) and the abandoned word resets
to untouched. Only a key that continues nothing anywhere is a wrong-key flash.

**Input.** `Keyboard.onTextInput`, not key codes — so an AZERTY player types the letters they see and
the on-screen QWERTY graphic stays a purely visual reference.

**Pause.** Escape or the HUD's PAUSE button. `Time.timeScale = 0` stops falling, spawning and the
boss's attack timers in one move, while UI, background scroll and audio keep running on unscaled
time. Typing is gated separately so a paused game can't be played through. Every exit path clears
the pause, and `GameManager.PlayLevel`/`GoHome` reset `timeScale` again — no future exit can strand
the game frozen.

**Music level follows game state.** Full volume only during `GameState.Playing`; menus, pause and the
end-of-run panels run at `AudioManager.OutOfGameMusicScale` (half). Context and the sting duck are
separate multipliers over the player's saved level, so neither can overwrite the other.

## Campaign: seasons, ranks and bosses

**80 levels — 4 seasons of 20.** Spring → Summer → Autumn → Winter. Levels 1–19 of each season are
ordinary; level 20 is the season boss. A global level number (1–80) stays the single source of
truth; `SeasonCatalog` maps it onto season + position, so nothing stores a pair.

**Ranks restart every season** and climb over the 19 ordinary levels — 1–5 `D`, 6–10 `C`, 11–15 `B`,
16–19 `A` — and level 20 alone is `S`. The rank describes the *boss's aggression*, not the
vocabulary.

**Difficulty ramps twice.** Fall speed and spawn cadence ramp across the 20 levels of a season and
restart each season, mirroring the rank arc — but each season multiplies from a higher floor
(×1.00 / ×1.15 / ×1.30 / ×1.45), so the campaign still gets harder level by level end to end. The
season boss adds a further spike. Word difficulty keys off the *global* level instead, so vocabulary
only ever climbs.

### The season owns the presentation

The theme is **not a setting** — Settings deliberately has no theme picker. Each season carries its
own palette asset (`Theme_spring/summer/autumn/winter`), and `ThemeManager` applies the palette of
whatever season is being played: `GameManager.PlayLevel` keys it off the level, the menu wears the
season the campaign stands in, and beating a season boss flips the whole game to the next season's
look **immediately, mid-celebration** (see the rank-up interstitial below). Replaying an old
season's level replays that season's look.

Two more systems make a season change *play* differently, not just read differently:

- **Seasonal weather** — `Fx/SeasonalAmbientFx` drifts pooled motes between the backdrop and the
  play content in both scenes: blossom petals (Spring), rising heat embers (Summer), tumbling
  leaves (Autumn), snow (Winter), tinted from the active palette.
- **Season wind on words** — `WordSpawner` hands every spawned word a sway profile: Spring drops
  clean (the baseline you learn on), Summer shimmers (±10 px), Autumn gusts hard (±30 px), Winter
  floats slow (±18 px). Combined with the per-season speed floors, a new season is a sharp,
  immediate gameplay turn.

### Rank-up interstitial

Beating the **last level of a rank** (in-season 5, 10, 15, 19) plays a full-screen interstitial
(`UI/RankUpUI`): "RANK D CLEARED", a motivational line, and a **live teaser of the next rank's
boss** — a real `BossUI` bound to the next level's actual generated definition, patrolling a
confined strip with its real sigil letter. Beating the **season boss** upgrades the interstitial
into the season handover: "SPRING CONQUERED" flashes into "SUMMER RISES" as the palette flips live.
Any key (after a short grace) or CONTINUE dismisses it, then the ordinary level-complete panel
takes over.

### Campaign finale

Beating **level 80 — Winter's Dragon — replaces the level-complete panel entirely** with the
finale (`UI/FinaleUI`): "ALL SEASONS CONQUERED" and a gold-flash "YOU ARE THE HERO" coronation, a
thirty-word tribute that **types itself out word by word** with the game's own key tick, the five
defeated creatures rising one by one to take a bow, and the run/best score. It tells the player
plainly that no remaining level is a match for them, and offers two exits: **START A NEW JOURNEY**
(two-tap confirm, wipes progress and drops straight into Spring 01 with the Spring palette) or
**HOME** (keeps the completed save for replaying any level). Replaying level 80 replays the finale.

### The boss

Every level has one, derived deterministically from the level number.

| Piece | Rule |
|---|---|
| **Health** | The win condition. Derived from the level's word queue, so a level still runs about 20 words. |
| **Damage** | A cleared word deals its length. A word containing the boss's **sigil letter** deals ×1.5 — and scores ×1.5. |
| **Sigil** | Chosen so ~45% of the level's words contain it: common enough to chase, rare enough to matter. |
| **Look** | An authored pixel-art creature per rank (see below), sigil badge hanging beneath it, patrolling the top of the play area. |
| **Attacks** | Fire on a timer, telegraphed ~1.4s ahead under the body. Cadence tightens with rank: `D` every 28s → `S` every 10s. |
| **Throws** | Words spawn from wherever the boss currently is and fan outward, so its patrol decides the board. |
| **Enrage** | Season bosses only: below 30% health the attack interval drops to 60%. |

**The three attacks**, unlocked one per rank so every rank block teaches a new threat:

- **Word Burst** (`D`+) — several words at once. Each is aimed at its own column at least 250px from
  its neighbours, centred on the boss and slid to fit on screen; leaving the spread to random
  velocities put them within a word's width of each other and they piled up illegibly.

  Columns alone were not enough: a drip racing a burst, a double attack's two volleys, or the
  edge clamp squeezing long words could still land two words on the same spot. Every spawned word
  now passes one final **separation gate** (`WordSpawner.ResolveDestination`): anything arriving
  into the same height band is pushed at least 230px clear of where its neighbours will settle
  (their *planned* landing spots, not their mid-throw positions), falling back to the least-bad
  slot on a genuinely full screen.
- **Speed Surge** (`C`+) — everything on screen falls faster for a few seconds.
- **Word Veil** (`B`+) — words' unread letters are replaced with `#`. Never the locked word, and the
  keyboard still highlights its next key, so a veiled board is always playable.
- `A` fires **paired attacks**; `S` has everything plus the enrage.

> A fourth attack, **Key Jam**, was removed on request. It is gone entirely — enum, tuning fields,
> router state and keyboard visuals — rather than left disabled. Note that `BossAttack` **and**
> `BossRank` are stored as ints in `BossTuning.asset`, so renumbering either requires regenerating
> that asset (dropping rank `E` did exactly this).

**Every rank is a different creature, not a bigger copy of the same one.** The bosses are
**authored pixel-art sprites** in `Assets/Art/Bosses/` (640×640, transparent, point-filtered —
the bootstrap pins those import settings but never generates or overwrites the art). `BossUI`
gives each creature its own size, patrol character and idle motion, and hangs the sigil badge
beneath it; each rank's UI colour (HUD badge, level grid, sigil ring, rank-up screen) is drawn
from its creature's palette:

| Rank | Creature | File | Size / patrol | Idle |
|---|---|---|---|---|
| `D` | **The Slime** | `D-shilliq.png` | 115 px, slow crawl | Squash and stretch |
| `C` | **The Thorn** | `C-tikan.png` | 130 px, quicker roll | Wobble-spin ±10° |
| `B` | **The Witch** | `B-jodugar.png` | 150 px, floaty swoops | Sways as she floats, biggest bob |
| `A` | **The Golem** | `A-golem.png` | 170 px, heavy march | Slow breathing, barely bobs |
| `S` | **The Dragon** | `S-ajdar.png` | 205 px, fastest sweep | Wingbeat pulse with a menacing roll |

`BossController` owns the rules and knows nothing about the play area — it decides *that* an attack
happens and of which kind; `LevelRunner` translates that into spawner, router and keyboard effects,
and `BossUI` owns the body. That is what keeps the fight testable without a scene.

Because the boss took the top band, the fall shortened from 680 px to 536. `LevelTuning`'s speeds
were scaled by that same ratio (×0.788), so fall *duration* — what the curve was tuned against — is
unchanged. Adjust `SceneBuilder.BossPatrolY` / `SpawnY` and you must rescale them again.

Balance lives in `Assets/Data/BossTuning.asset` (per-rank profiles) and
`Assets/Data/LevelTuning.asset` (speed, cadence, season scaling) — **see the tuning-asset caveat
below before assuming a code change reached them.**

## Decisions worth knowing

These either resolve something the brief left open or deviate from it. All are cheap to reverse.

1. **The boss's health is the win condition, not a word count.** Clearing words is how you damage
   it. This also resolves the original contradiction in the brief — "clear 20" *and* "3 misses ends
   the run" would, taken literally, make one miss fatal to a 20/20 goal. The word queue simply runs
   long (`wordsPerLevel + maxMisses + spare`) and the spawner tops the screen up until the boss
   falls or three words are missed.
2. **`LevelTuningSO` instead of the brief's `LevelDataSO`.** Levels are generated, not authored, so
   the asset holds the *tuning constants* (§5) and `LevelData` is a plain generated object.
3. **No DOTween.** §2 suggests it, but it is an Asset Store `.unitypackage` with no UPM path, which
   would have made the project non-buildable offline. `Fx/Juice.cs` provides the punch/shake/fade
   easings instead. Call sites are confined to `Fx/`, `UI/` and `WordController`, so swapping in
   DOTween later is mechanical.
4. **Canvas is Screen Space – Camera**, not Overlay, so URP Bloom actually affects the neon UI and
   falling words. Overlay canvases bypass post-processing entirely.
5. **All audio is synthesised at runtime, not imported.** `ProceduralMusic` builds a seamless 8-bar
   synthwave loop in A minor (Am–F–C–G: pad, octave bass, 16th arpeggio, four-on-the-floor drums,
   and a bell lead entering in the second half), and `ProceduralSfx` builds the key/clear/miss/UI
   cues plus level-complete and game-over stings, pitched to the same key so they sit with the
   music. This is deliberate: downloaded music carries licensing that has to be cleared before
   shipping — the same trap flagged for the word list below — and it keeps the repo free of binary
   audio. `AudioManager` prefers an assigned clip over a generated one, so authored music and SFX
   drop straight in without touching any of this.
6. **The clear burst is pooled uGUI images, not a ParticleSystem.** The play area is a Screen Space –
   Camera canvas, where a ParticleSystem needs its own renderer ordering and doesn't sort cleanly
   against UI. `Fx/ShardBurst` pools images that share the canvas batch and cost nothing per burst.
7. **The level grid is anchored proportionally, not in fixed pixels.** CanvasScaler's match-0.5 mode
   shrinks the reference width below 1920 on anything taller than 16:9 (a 16:10 window gives ~1827),
   so a grid laid out against a fixed 1920 loses its outer columns. Sizes live in the constants at
   the top of `SceneBuilder`; keep the grid's total width inside the 58% area at every aspect.
8. **Four 2D packages were removed** from `manifest.json` (`2d.animation`, `2d.spriteshape`,
   `2d.tilemap.extras`, `2d.aseprite`). They ship with the 2D template but do not compile against
   Unity 6000.5.8f1 — 90 errors, including hard `InternalEngineBridge` signature breaks. None are
   used by a TMP/uGUI typing game. **Do not re-add them** without checking they have caught up.
9. **The `LOCK` badge on locked levels is a placeholder plate**, not real art.
10. **The theme picker was removed on request** — seasons own their palettes and beating a season
    is the only way to change the look. `SaveData.themeId` is gone with it; old save files still
    parse (JsonUtility ignores unknown fields) and progress past level 80 clamps to the new final
    level.

## ⚠️ The word list is not cleared for commercial release

`Assets/Data/WordLists/google-10000-english-usa-no-swears.txt` is frequency-ranked (line number ==
rank, which drives the difficulty tiers). Its licence permits *"educational and personal/research
use"* and explicitly advises against commercial use without an LDC licence.

**Fine for development. Must be replaced or licensed before shipping commercially.** Swapping is a
one-field change — see `Assets/Data/WordLists/README.md` for permissively licensed alternatives and
the `rankingMode` flag for unranked lists.

Fonts (Orbitron, Rajdhani, Share Tech Mono) are all SIL OFL and carry no such restriction; their
licences are vendored alongside them in `Assets/Fonts/`.

### Validating generated wiring

Because the scenes are generated, a mis-wired reference produces no compile error. This walks every
Typing Me component in both scenes and all prefabs, fails on unassigned references, and asserts the
per-scene invariants (exactly one `AudioListener`, `Camera`, `EventSystem`, `Canvas` and `Volume`):

```bash
/Applications/Unity/Hub/Editor/6000.5.8f1/Unity.app/Contents/MacOS/Unity -batchmode -quit -projectPath /Users/imac/Developer/typer -executeMethod TypingMe.EditorTools.SceneValidator.Validate -logFile /tmp/validate.log
```

Also available as **Typing Me → Validate Generated Assets**.

> **The gotcha those invariants exist for.** The Editor quietly adds components that
> `new GameObject(typeof(Camera))` does not — "Create → Camera" attaches an `AudioListener`, code
> does not. The project shipped completely silent because of this: every `AudioSource` reported
> `isPlaying == true` and there was simply no listener to render it. `isPlaying` is not evidence of
> sound; `AudioManager` now reads the mixed output back through the listener at boot and logs
> `audible` or `SILENT` with the reason. Note the mix reads as silence for the first ~2 seconds
> while the audio engine warms up, so that check retries before drawing a conclusion.
